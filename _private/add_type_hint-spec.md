# 外部仕様書: 型ヒント追加

## 1. 目的
本仕様書は、`src/yklibpy` 配下の Python ソースコードに対して、クラスのメソッドおよび関数の引数・返値に型ヒントを記述するための要求事項を定義する。

本作業の目的は、静的解析の適用範囲を明確にし、呼び出し側と実装側の契約を読み取りやすくすることである。

## 2. 背景
要求元は `_private/20260313/add_type_hint-req.md` である。

本リポジトリは Python 3.14 を前提とし、`pyproject.toml` で `mypy` strict mode と `ruff` を利用する。したがって、追加する型ヒントは既存の型検査方針と整合していなければならない。

## 3. 対象範囲
対象は `src/yklibpy` 配下の `.py` ファイルとする。

対象となる記述は以下のとおりとする。

- モジュールレベル関数
- クラスのインスタンスメソッド
- クラスメソッド
- スタティックメソッド
- 特殊メソッド `__init__`
- 既存コードに存在する公開・非公開メソッド

以下も対象に含む。

- すでに一部だけ型ヒントが付いているシグネチャの不足箇所
- 引数は注釈済みだが返値注釈が欠けている定義
- `__init__` における `-> None` の欠落

## 4. 非対象
本作業では、原則として以下を対象外とする。

- 関数やメソッドの振る舞い変更
- 大規模なリファクタリング
- API 名称変更
- データ構造全体の再設計
- 型精度向上のみを目的とした大規模な `TypedDict`、`Protocol`、独自クラスの新設
- docstring の全面改訂

ただし、型ヒント追加の結果として静的解析上の不整合が顕在化し、最小限の修正なしでは整合が取れない場合は、その修正を許容する。

## 5. 型ヒント記述方針
型ヒントは Python 3.14 を前提とした現代的な構文で記述する。

- `X | None` を用いる
- `list[str]`、`dict[str, Any]` のように組み込みジェネリクスを用いる
- 互換性上の理由がない限り、`Optional`、`List`、`Dict` など旧来の型表記へ新規に寄せない
- 返値がない関数・メソッドは `-> None` を明記する
- `*args`、`**kwargs` にも可能な範囲で型を付ける

## 6. 既存注釈の扱い
既存の型注釈は、以下の方針で扱う。

- 欠落している引数型・返値型は補完する
- 明らかに不完全な注釈は修正してよい
- 既存注釈が動作契約と整合している場合は維持する
- `Any` を使用している箇所は、実データ構造が安定していない場合に限り維持してよい

`Any` を安易に増やしてはならない。ただし、YAML、TOML、HTML パース結果のように入力構造が動的で、既存コード上も厳密な型境界が表現されていない箇所では、無理に詳細化しない。

## 7. 動的データに対する許容
以下のような動的データを扱う箇所では、過度に細かい型定義を必須としない。

- YAML 読み込み結果
- JSON 読み込み結果
- TOML 読み込み結果
- BeautifulSoup の要素オブジェクト
- 外部コマンドや外部入出力に由来する値

この場合は、`Any`、既存ライブラリ型、または現実的に表現可能な広めの共用体型を用いてよい。

## 8. 実装上の制約
型ヒント追加にあたり、以下を満たすこと。

- 既存の公開 API の呼び出し方法を変更しない
- 既存の import 構成を不必要に複雑化しない
- 型ヒント追加のためだけに新しい外部依存を導入しない
- 厳密化が困難な箇所でも、少なくともシグネチャ上の引数型・返値型は明示する

## 9. 受入条件
本仕様の完了条件は以下のとおりとする。

- `src/yklibpy` 配下の対象関数・対象メソッドの全シグネチャに引数型が記述されている
- `src/yklibpy` 配下の対象関数・対象メソッドの全シグネチャに返値型が記述されている
- すべての `__init__` に `-> None` が記述されている
- 型ヒント追加によって既存の公開 API 互換性を不必要に損なっていない
- 型ヒント追加後のコードが `pyproject.toml` の `mypy` strict 方針および `ruff` 方針と矛盾しない

## 10. 検証方法
検証は少なくとも以下の観点で行う。

- 対象モジュールを走査し、引数型と返値型の欠落がないことを確認する
- `mypy src/yklibpy` で重大な型エラーを発生させないことを確認する
- `ruff check src` で新たな lint エラーを発生させないことを確認する

## 11. 注意事項
本仕様は「すべての不足注釈をなくすこと」を主目的とする。

既存の広い型を、常により厳密な型へ置換することまでは要求しない。厳密化によって大きな設計判断が必要になる場合は、その箇所を保留扱いにし、別要求として切り出す。

## 12. 想定される要注意領域
以下のようなモジュールでは、動的データや汎用コンテナが多く、厳密型付けよりも実用的な型付けを優先する。

- `src/yklibpy/common/util.py`
- `src/yklibpy/db/appstore.py`
- `src/yklibpy/db/storex.py`
- `src/yklibpy/htmlparser/configprepare.py`
- `src/yklibpy/tomlop/tomlop.py`

以上を、本要求に対する型ヒント追加作業の外部仕様とする。
